# Task: Scan pushdowns — filter, projection, limit, TopN, region pruning

## Description

Implement the non-aggregate pushdown surface in `FederationMetadata`:
`applyFilter`, `applyProjection`, `applyLimit`, `applyTopN`, including `_region` pruning.

## Acceptance Criteria

- [ ] `applyFilter`: extracts pushable `TupleDomain` into the handle (types the SQL builder can
      render); non-pushable domains returned as remaining constraint. Domain on `_region` prunes
      the handle's region list and is consumed (not sent to regions, not left as remainder)
- [ ] `WHERE _region = 'a'` on a 2-region setup contacts only region a (asserted via regional
      query counting in tests)
- [ ] `applyProjection`: prunes handle columns to referenced subset (plain column references only;
      dereferences not supported in v1)
- [ ] `applyLimit`: stores limit in handle, returns `limitGuaranteed=false` so engine applies the
      final LIMIT
- [ ] `applyTopN`: stores sort items + count when all sort columns are pushable types, returns
      `topNGuaranteed=false`; regional SQL gets `ORDER BY … LIMIT n`
- [ ] Idempotency guards: repeated apply calls with no change return `Optional.empty()` (no
      planner loops)
- [ ] Pushdown interplay: filter+limit+topN compose in one handle and in generated SQL

## Technical Details

- TopN after limit or vice versa: follow base-jdbc semantics (TopN supersedes plain limit).
- Sort items on `_region` are pushable per-region only as a constant — simplest correct choice:
  refuse TopN pushdown if sort references `_region`.
