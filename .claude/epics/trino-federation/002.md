# Task: RegionClient — Trino client protocol wrapper and type mapping

## Description

Build the transport layer used by both metadata and data paths. `RegionClient` wraps
`io.trino.client.StatementClient` for one configured region: execute a SQL string against the
region's remote catalog, stream result rows, expose column metadata. Includes the type-mapping
layer (`ClientTypeSignature` → Trino `Type`) and row→`Page` conversion via `PageBuilder`.

## Acceptance Criteria

- [ ] `RegionClient.execute(sql)` returns a streaming handle: column names/types + row iterator;
      resources closed on completion, cancellation propagated to the region
- [ ] Type mapping covers: boolean, tinyint/smallint/integer/bigint, real/double,
      decimal(p,s), varchar(n)/varchar, varbinary, date, time, timestamp(p),
      timestamp(p) with time zone; unsupported types surfaced distinctly so metadata can skip them
- [ ] Value conversion from client JSON representations to Trino stack types (longs, Slices,
      LongTimestamp etc.) correct for all mapped types — unit-tested round-trip against an
      embedded `TestingTrinoServer`
- [ ] Errors carry region name and remote error message in a `TrinoException` with a
      federation error code enum
- [ ] Listing helpers: `listSchemas()`, `listTables(schema)`, `describeTable(schema, table)`
      implemented via information_schema queries against the remote catalog

## Technical Details

- Follow `trino-jdbc`'s use of `StatementClient` (OkHttp client setup, session builder) for
  reference; auth = user + optional basic auth password; honor configured timeouts.
- One shared HTTP client; per-query `StatementClient` instances.
- Keep the client synchronous-streaming; concurrency is handled by callers (splits / fan-out
  combine executor).
