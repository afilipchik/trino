# Task: Metadata, handles, and _region column

## Description

Implement `FederationMetadata` and the handle types. Schema/table/column listing delegates to
`RegionClient` listing helpers against the first reachable region (homogeneous-shard assumption),
with a short-TTL cache. Every table gets a synthetic `_region` VARCHAR column appended.

## Acceptance Criteria

- [ ] `listSchemaNames`, `listTables`, `getTableHandle`, `getTableMetadata`, `getColumnHandles`,
      `streamTableColumns` work against embedded regions
- [ ] `FederationTableHandle` (JSON-serializable): schema, table, columns snapshot, active region
      list, `TupleDomain` constraint + non-pushable remainder flag, `OptionalLong limit`,
      optional TopN (sort items + count), optional aggregation spec (filled by task 007)
- [ ] `FederationColumnHandle`: remote name, Trino type, `isRegionColumn` flag; `_region` appears
      in `getColumnHandles`/table metadata as a regular selectable column
- [ ] First-region metadata failure fails over to next region; all-regions-down produces a clear
      `TrinoException` naming attempted regions
- [ ] Columns with unmappable remote types are omitted from listing (logged once)

## Technical Details

- Cache via Guava `CacheBuilder` (few seconds TTL, config-tunable later — hardcode constant v1).
- Handle records: prefer Java records with `@JsonCreator`-compatible canonical constructors,
  matching repo conventions.
- Table handle must carry everything the SQL builder needs so `RemoteSqlBuilder` stays engine-free.
