# Task: Kind demo — central + regional clusters

## Description

Extend the kind deployment assets from the kubernetes-connector epic with a multi-region
federation demo: `trino-region-a` and `trino-region-b` clusters (Deployments/Services in the same
kind cluster, acting as "regions"), each exposing a memory-connector shard of a TPC-H-derived
dataset, plus the central Trino carrying a `federation` catalog pointing at both services.

## Acceptance Criteria

- [ ] Manifests: two regional Trino deployments + services; regional data seeded on startup
      (init SQL splitting `tpch.tiny.orders`/`lineitem` by key range so shards are disjoint)
- [ ] Central Trino image/config includes the freshly built `trino-federation` plugin and a
      `federation.properties` catalog listing both regions by service DNS
- [ ] `setup` script (extending the existing kind demo script) stands everything up from scratch
- [ ] Verification script runs and prints: unioned `count(*)` vs per-region counts,
      a grouped aggregate, a `_region`-filtered query, and per-region rows-shipped evidence
      (from regional `system.runtime.queries` output bytes/rows)
- [ ] README section documenting the demo flow

## Technical Details

- Reuse the existing kind script patterns (image build/load, waits) from
  the kubernetes-connector demo assets; keep regional clusters single-node with small heap.
- Regional seeding: `memory` catalog + post-start `trino --execute` Job or init container.
