# Task: Multi-cluster integration test suite

## Description

Comprehensive IT harness: `FederationQueryRunner` builds N "regional" `DistributedQueryRunner`s
(memory connector loaded with disjoint per-region shards of TPC-H-derived data) plus one central
runner with the federation catalog pointed at the regions' HTTP addresses. Test classes cover
correctness and every pushdown class. (Harness skeleton can begin once task 005 lands; full suite
needs 007.)

## Acceptance Criteria

- [x] Harness: 2 embedded regions + central, reusable across test classes; regional query log/
      counter hook to assert what SQL each region received and how many rows it returned
- [x] Correctness: unioned SELECT equals expected UNION ALL; `_region` values; ORDER BY/LIMIT/
      aggregations match results computed over a single-cluster control table
- [x] Pushdown plan assertions (plan-pattern or `isFullyPushedDown`-style where applicable) for
      predicate, projection, limit, TopN, aggregation
- [x] Region pruning: `WHERE _region='a'` → region b receives zero queries
- [x] Data-movement assertions: `count(*)` ships 1 row/region; grouped agg ships ≤ groups/region
- [x] Fallback correctness: `count(DISTINCT x)`, `sum(x) FILTER (…)`, unsupported types produce
      correct results without pushdown
- [x] Failure modes: one region down → query fails with error naming the region

## Technical Details

- Regional data loading via `CREATE TABLE region_x AS SELECT … FROM tpch.tiny.orders WHERE …`
  splits (e.g. by orderkey ranges) into the memory connector.
- Regional query counting: simplest is querying each region's `system.runtime.queries` /
  event listener; pick whichever is least flaky.
- Suite must run in CI: no containers, moderate memory (2 small DQRs + 1 central).
